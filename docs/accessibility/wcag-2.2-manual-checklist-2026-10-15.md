# WCAG 2.2 A/AA manual assessment checklist

Assessment date: 15 October 2026\
Scope: OpenScribe web application, representative login, workspace, Scribe, review and copy workflows, plus browser-mediated microphone interaction where used. This is a working assessment record, not a conformance claim or legal scope determination.

## Assessment method and limits

Each WCAG 2.2 Level A and AA success criterion is listed below. “Not tested” means a reviewer has not established the outcome from sufficient evidence; automated axe coverage does not convert a criterion to pass. The 15 October pre-remediation browser pass found one scoped 2.4.7 failure and one scoped 4.1.2 accessibility-tree concern; it did not assess those criteria across the full product. No criterion is marked passed. A criterion may be marked “Not applicable” only with a recorded reason after the organisation confirms product scope. Supported screen-reader/OS/browser testing and native microphone permission UI remain open.

Use the evidence field to record a reproducible page/workflow, test method, browser and assistive technology versions, date, and sanitized artifact reference. Do not include patient data, credentials, cookies, page dumps, or screenshots containing user content. Assign a named reviewer before closing each item.

Owners below are role assignments for follow-up, not named individuals. The organisation should assign people before treating this as a completed assessment.

The [interactive browser assessment addendum](interactive-browser-assessment-2026-10-15.md) records limited Playwright MCP keyboard, dialog, 320 CSS pixel reflow, and text-spacing spot checks on an isolated synthetic session. It identifies a clipped keyboard-focused Recording mode select and a note-version switcher whose name is absent from the browser accessibility snapshot. These findings do not change any criterion disposition below: this assessment still lacks complete criterion-level evidence, visual review, and supported assistive-technology testing.

## Automated evidence boundary

Opt-in axe reports are supplementary evidence for the DOM states, rules, and tags actually scanned. They do not assess the complete WCAG criterion in all states and do not replace keyboard, zoom/reflow, assistive-technology, native browser/OS, document, or human content review. See the dated evidence manifest for reports actually reviewed and hashed.

## Organisation decisions still required

- Confirm accessibility assessment scope, including exported/downloaded documents, supported browsers/themes, and any embedded or third-party content.
- Assign named owners and review dates for the untested items.
- Decide legal/regulatory applicability separately; this checklist does not make that determination.
- Test screen-reader flows with a supported combination and native microphone permission prompts on the target operating system/browser.

## Normative reference

The checklist follows the WCAG 2.2 Recommendation. WCAG 2.2 removed 4.1.1 Parsing; it is intentionally not listed as an applicable criterion. Confirm criterion names/levels in the [W3C WCAG 2.2 Recommendation](https://www.w3.org/TR/WCAG22/). W3C states that Level AA requires all Level A and AA success criteria to be met; this record makes no such claim.
